# تلاش دی‌کامپایل ایستا

این پوشه نتیجهٔ واقعی یک تلاش برای دی‌کامپایل فایل است، نه سورس بازیابی‌شدهٔ برنامه. ابزار angr فقط ۲۴ گره و ۷ تابع در تحلیل محدود به نقاط قابل دسترسی پیدا کرد. خروجی خام در [`decompiler-output.txt`](decompiler-output.txt) است. در آن نام‌هایی مانند `sub_1be8304` نام‌های خودکار ابزار هستند و عبارت‌هایی مانند `vvar_2{r28|4b}` یا `goto` غیرمستقیم، خروجی ناقص تحلیل‌اند؛ این متن یک پروژهٔ C قابل کامپایل یا توصیف قابل اعتماد کل برنامه نیست. کامنت‌های `do not return` هم استنباط ابزار هستند، نه نتیجه‌ای قطعی. به‌دلیل پرش‌های غیرمستقیم و محافظت احتمالی، این تحلیل همهٔ کد برنامه را پوشش نمی‌دهد.

در این آزمایش، unicorn بارگذاری نشد و angr پیام خطا داد؛ این پیام در خروجی باقی مانده است. در این تحلیل ایستا از اجرای unicorn استفاده نشده است، ولی خروجی همچنان ناقص است.

## مشاهدات تکمیلی

- فرادادهٔ Version در فایل از `Nexida Loader`، محصول `Nexida` و نسخهٔ `1.2.9124` نام می‌برد؛ این‌ها صرفاً متن ثبت‌شده در فایل هستند.
- آدرس نقطهٔ ورود، با image base فایل، `0x12c93d3` است. یک TLS callback در `0x1240a76` ثبت شده است که ویندوز می‌تواند پیش از نقطهٔ ورود فراخوانی کند.
- دستور اول نقطهٔ ورود `jmp 0x1be8304` است. در آن مقصد یک `push` و یک `call` به آدرس دیگری وجود دارد. دی‌کامپایل این نقاط به منطق کاربردی برنامه نرسید.
- بخش `.Dfw5b` حدود ۱۰ مگابایت است و آنتروپی حدود ۷٫۹۸ بیت بر بایت دارد. این مشاهدات با محافظت/مبهم‌سازی سازگارند، ولی نوع یا میزان آن را ثابت نمی‌کنند.

## دنبال کردن یک مسیر شبیه‌سازی‌شده

علاوه بر دی‌کامپایل، [`synthetic_trace.py`](synthetic_trace.py) یک مسیر از نقطهٔ ورود را با شبیه‌سازی angr دنبال می‌کند. خروجی ثبت‌شده در [`synthetic-trace.txt`](synthetic-trace.txt) پس از سقف ۱۲٬۰۰۰ گام متوقف شد و به کد قابل انتساب به منطق اصلی برنامه نرسید. هر خط نمونهٔ هر ۱۰۰ گام است، نه همهٔ دستورهای اجراشده.

این آزمایش **اجرای واقعی در ویندوز نیست**: مستقیماً از نقطهٔ ورود شروع می‌شود، TLS callback را اجرا نمی‌کند، stack ساختگی دارد و رجیسترها و حافظهٔ نامشخص را صفر فرض می‌کند. در اولین چندشاخه‌شدن یا آدرس کنترلِ نامشخص متوقف می‌شود. بنابراین مسیر حاصل ممکن است با اجرای واقعی متفاوت باشد و از آن نمی‌توان دربارهٔ رفتار کامل یا کارکرد برنامه نتیجه‌گیری کرد. پیام خطای مربوط به unicorn در خروجی حفظ شده است؛ این آزمایش از موتور VEX استفاده می‌کند.

منابع واقعی آیکون، manifest و متن نسخه هم در [`../recovered-resources/`](../recovered-resources/) استخراج شده‌اند.

## تکرار آزمایش

از ریشهٔ مخزن و در محیط Python مجزا:

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install 'angr==9.2.213' 'bitstring==4.4.0' 'pycparser==3.0'
python analysis/decompile_entry.py
python analysis/synthetic_trace.py
```

اسکریپت قبل از تحلیل هش فایل را بررسی می‌کند. کتابخانه‌ها و تحلیل‌گر تغییر می‌کنند و خروجی ممکن است با نسخه‌ها یا محیط‌های دیگر فرق کند. اسکریپت برنامهٔ ویندوزی را اجرا نمی‌کند، بلکه گراف جریان و شبه‌کد را به‌صورت ایستا تخمین می‌زند.
